# Audit

This is a self-audit of Penstock at the end of development, done on 2026-11-01 and extended on 2026-11-02 (rows 43–47, interface refinement pass; rows 48–50, 1Click re-check against the official docs; rows 51–55, live-path audit after the first real payment and refund; rows 56–62, real data on the hosted site). Each item says what was checked and how. "Fixed" means a code change landed with a regression test. "Held" means the existing design already handled it and a test proves it. "Remains" means it is not solved and is stated plainly.

Tests: `pnpm test` runs 139 tests in 26 files. The hosted static build is checked by `pnpm audit:static` (after `pnpm build:static`). The audit-specific tests are in `apps/proxy/test/audit.test.ts`.

## What remains

- **Origin-chain observation:** Penstock trusts 1Click `GET /v0/status` for deposit detection. The near-intents draft asks the facilitator to observe the origin chain itself.
- **Single-node claims:** exactly-once guarantees hold within one SQLite ledger. Several proxy instances would need one shared database.
- **Upfront flow:** if the upstream fails after settlement, the buyer has paid and the operation is marked executed. The buyer keeps a signed receipt, and recovery is between buyer and seller. This is the documented behaviour of the `upfront` payment flow.
- **Session trust:** the seller holds session funds (at most the cap) until close. In live mode refunds are "owed" and the seller sends them. An escrow contract would remove this trust; it is not built.
- **Header size:** the 402 `PAYMENT-REQUIRED` header is about 10 KB. Some reverse proxies need larger header buffers.
- **Real view depends on public RPCs:** the browser reads come from two free public NEAR RPCs with no SLA. If both are down the page falls back to cached values, labelled. `proof.json` is a snapshot of the 2026-11-02 run; the seller's live balance can differ from it later, which is the point of reading it live.
- **Hosted demo CSP needs Cloudflare:** the CSP lives in `_headers`, which Cloudflare Workers static assets apply. Other static hosts need equivalent headers configured.
- **Hosted demo receipt times:** build-time receipts keep their build-time timestamps, while the snapshot's rows are shifted to look recent. The receipt drawer says so.
- **Demo and dry are not paid services:** anyone who can reach them can make simulated deposits. They bind to loopback by default; do not expose them.
- **Live end to end:** run on mainnet once for a payment and once for a refund, both on the Solana USDC route (docs/PROOF.md). Other origin chains were checked with real dry quotes only.
- **Live bind address:** live mode listens on `0.0.0.0` by default. The proof runs set `HOST=127.0.0.1`; anyone testing live should do the same until the proxy sits behind a reverse proxy they control.
- **Unattended resume:** `live:pay` stops polling after 20 minutes; a payment still pending then is finished by running `pnpm live:pay resume` again (it is never resent).
- **Shielded scope:** shielded mode hides the payer's origin and route only. The USDC delivery to the seller and the seller's revenue stay public. The Aurora route cannot pay until 1Click supports such chains.
